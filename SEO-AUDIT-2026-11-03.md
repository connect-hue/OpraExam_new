# OPRAExam.in SEO and traffic audit

Audit date: 3 November 2026 (Asia/Calcutta).

## Scope and limits

Reviewed the Next.js 16.2.1 source, public routes, MongoDB content helpers, CMS publishing routes/editor, metadata, structured data, navigation, quiz, lead capture, download flow and installed Next.js metadata documentation. Fetched all 33 public HTML pages discovered from the blog listing and public routes: 9 core/legal pages and 24 articles. Also checked live robots.txt, sitemap.xml, domain redirects, two nonexistent URLs and the icon URLs referenced by production.

This is a source and HTTP audit, not a visual browser test. No application code, CMS records or production settings were changed. No lead forms were submitted. Search Console, GA4 reports, server logs and backlink data were unavailable. Therefore this report identifies defects and growth opportunities; it does not establish why traffic changed or which keywords have the greatest measured demand. The public PageSpeed API returned HTTP 429 (quota exceeded), so no Lighthouse or Core Web Vitals score is claimed. Response body sizes below are decoded HTML sizes, not compressed transfer sizes or speed scores.

## Assessment

The site has useful foundations: server-rendered information, dedicated syllabus/dates/practice pages, metadata, blog discovery links, structured data and working domain redirects. Its most urgent gaps are conflicting educational information, inconsistent canonical signals, incomplete sitemap coverage, unsupported template-wide reviewer claims, and unreliable conversion handling. Increasing article volume before addressing these issues would reproduce the same weaknesses.

## Priority 1: correct content and trust claims

### 1. Calculator guidance conflicts with APC

Live article: https://www.opraexam.in/blog/can-you-use-a-calculator-in-opra-exam

The article prohibits physical scientific calculators and describes the on-screen calculator as lacking scientific functions. APC currently permits standard/scientific calculators subject to restrictions and lists both standard and scientific online calculators. The homepage already describes permitted calculators differently from this article.

Change the MongoDB article, associated FAQs and any cross-linked preparation advice. Check the exam-day checklist and related calculator references. Record a real review date and cite the specific APC rule. This article also needs the future-date correction described below.

Authority: https://www.pharmacycouncil.org.au/pharmacist/Exam-information/opra-exam-day-preparation/

### 2. Older syllabus guidance contradicts the main syllabus page

Live article: https://www.opraexam.in/blog/understanding-opra-exam-syllabus

This article presents three approximate groupings of 30%, 30% and 40%. APC's current five content areas are Biomedical Sciences 20%; Medicinal Chemistry and Biopharmaceutics 10%; Pharmacokinetics and Pharmacodynamics 10%; Pharmacology and Toxicology 15%; Therapeutics and Patient Care 45%. The main /syllabus page already uses the five-area structure.

Update the stored article and review older preparation/score/format articles for the same obsolete groupings. The books article also recommends a 90-second question pace; 150 minutes divided by 120 questions gives 75 seconds on average. Treat study targets as educational advice, not official pass thresholds. Review salary, migration and registration claims against their appropriate primary authorities separately.

Authority: https://www.pharmacycouncil.org.au/resources/opra-exam-guide-and-sample-content/

### 3. Reviewer credentials are applied automatically

Source: src/app/blog/[slug]/page.tsx:279-311; src/components/admin/BlogEditor.tsx:36; src/app/about/page.tsx.

Every article displays “AHPRA Registered”, “Clinical Pharmacy Reviewer”, practising in Australia and a clinical verification statement. These statements also appear for the generic author “OPRA Exam Specialist”. The profile link leads to the general About page rather than an individual reviewer profile. The template and public profile information do not substantiate these claims; this audit does not determine whether any named person is actually registered.

Replace automatic claims with verified author/reviewer records. Store actual identity, role, credentials, profile URL, review date and sources. Publish individual profiles and an editorial/corrections policy. Only display a registration or review statement where it is substantiated for that person and article. Use Organization authorship for a genuine editorial team rather than representing a generic label as a Person.

Google guidance: https://developers.google.com/search/docs/fundamentals/creating-helpful-content

## Priority 2: make discovery and metadata consistent

### 4. Canonical URLs conflict with production redirects

Source: src/app/blog/[slug]/page.tsx:10; src/app/opra-quiz/page.tsx:4; src/app/privacy/page.tsx:4; src/app/terms/page.tsx:4; src/app/robots.ts:5-8; src/app/layout.tsx:16; src/app/sitemap.ts:8.

Production redirects the alternate hostname to https://www.opraexam.in, while 27 pages canonicalize to https://opraexam.in. Those canonical destinations redirect back to www. Main pages and sitemap entries already use www. This is conflicting canonical evidence, not proof of a duplicate-content penalty.

Create one validated public origin configuration and use it for page canonicals, Open Graph URLs, schema IDs and sitemap/robots output. Align deployment environment variables too. Preserve the functioning permanent redirects. Verify every public canonical resolves directly to the preferred 200 URL and preserves the correct path.

Google guidance: https://developers.google.com/search/docs/crawling-indexing/canonicalization

### 5. Five published articles are absent from the live sitemap

Source: src/app/sitemap.ts:37-112; src/app/api/admin/blogs/route.ts; src/app/api/admin/blogs/[id]/route.ts.

Missing URLs:

- /blog/opra-pharmacology-toxicology-2027
- /blog/opra-biomedical-sciences-syllabus-mcqs-2027
- /blog/opra-therapeutics-patient-care-2027
- /blog/opra-exam-registration-process-2027
- /blog/opra-exam-calculations-formulas-practice-questions

The pages are linked from /blog and return 200, so they remain discoverable; absence from the sitemap does not prove Google has not indexed them. The local sitemap reads published blogs and declares 60-second revalidation. Inspect the deployed version, data source/environment and route/CDN caching to establish the discrepancy. CMS mutation handlers currently contain no explicit public-route revalidation.

After successful publish/update/unpublish/delete, invalidate affected article paths, home/blog listings and sitemap using the installed Next.js conventions. Handle old and new paths when a slug changes. Recheck sitemap output against published URLs after the deployment, then submit the preferred-host sitemap in Search Console. Do not alter lastmod unless content changed meaningfully.

### 6. Publication and modification dates are unreliable

Source: src/app/blog/[slug]/page.tsx:47,110-111,186; src/lib/db/blogs.ts:26-37,153-166; src/components/admin/BlogEditor.tsx:37-39.

All 24 articles emit human-readable date strings in datePublished/dateModified, rather than ISO date-time values. dateModified is always the publication display date, even though updatedAt exists. The calculator article is already published with a 31 December 2026 date, ahead of this audit date. Date-based sorting helps place it first in listings.

Store and validate publication timestamps separately from formatted display dates. Emit ISO 8601 dates with a timezone in schema, use the true editorial modification date, and format only the visible date. Correct the erroneous future date. If scheduling is intended, introduce explicit scheduling and exclude posts until their publication time; do not infer scheduling from an uncontrolled display string.

Google guidance: https://developers.google.com/search/docs/appearance/structured-data/article

### 7. Blog titles append two branding suffixes

Source: src/app/blog/[slug]/page.tsx:36; src/app/layout.tsx:36-38.

A live example ends with “| OPRA Success Strategy | OPRAExam.in”. The article generator appends one phrase and the root template appends another. Return a concise topic-specific title and allow a single site suffix, or deliberately use an absolute title. Preserve the useful topic at the beginning. Evaluate search CTR in Search Console rather than assuming a fixed character count guarantees display.

### 8. Imported article HTML creates oversized/duplicate H1 headings

Source: src/components/admin/RichTextEditor.tsx:332,405; src/app/blog/[slug]/page.tsx:171,207-213.

Seven articles have a template H1 plus another H1 inside CMS HTML. Several second H1s are full introductory paragraphs. Affected articles are pharmacology/toxicology, therapeutics, registration, biomedical sciences, retakes, Indian eligibility and calculations.

Keep the article title as the page H1. Convert introductory paragraphs to paragraphs and article subsections to H2/H3. Remove H1 formatting from article body controls and normalize pasted content on the server. Multiple H1s alone are not evidence of a Google penalty; the concrete issue is the poor document hierarchy and incorrect paragraph formatting.

## Priority 3: repair publishing and conversion infrastructure

### 9. Database errors are treated as missing content

Source: src/lib/db/blogs.ts:71-118; src/app/blog/[slug]/page.tsx:69-75; src/app/sitemap.ts:90-112.

Published-list failures return [], and article lookup failures return null. An operational failure can therefore look like a valid empty blog/sitemap or a nonexistent article. This is a source-level risk; the 33 live pages worked during this audit.

Distinguish genuine not-found results from database/service failures. Preserve last successful content during revalidation, surface/monitor operational failures, and return appropriate temporary failure behavior where no usable cached response exists. Avoid caching an outage as a valid deletion. Memoize repeated article lookups within one render and use limited/projected list queries as content grows.

### 10. CMS content/FAQ edits do not drive the corresponding public pages

Source: src/lib/db/siteContent.ts; src/lib/db/faqs.ts; src/app/api/admin/content/route.ts; src/app/api/admin/faqs/route.ts; src/app/page.tsx:40; src/app/syllabus/page.tsx:51.

Database helpers and admin routes exist, but the homepage and main FAQ arrays remain hardcoded and do not read those helpers. Connect the intended public sections to the CMS, or remove misleading editing controls. Keep visible FAQ answers and their schema generated from the same content. Add publish validation and appropriate cache invalidation so an editorial correction reaches the website.

### 11. Quiz lead capture treats failure as success

Source: src/components/QuizApp.tsx:349-371; src/components/LeadForm.tsx:125-146; src/app/api/leads/route.ts:131-173.

The quiz does not check the POST response status and sets its submitted flag in finally, including on failure. The reusable LeadForm already checks failure status more carefully. The CRM follow-up PATCH is fire-and-forget and does not inspect the response status.

Use a shared validated lead-submission path, show retryable errors, and acknowledge submission only after the intended backend outcome. Await reliable follow-up processing or use an appropriate durable/background mechanism. Review the quiz's hardcoded qualification and KAPS program values against CRM requirements. A visitor receiving a result should not silently disappear from lead reporting. No actual lead was sent during this audit.

### 12. Measurement stops at the Analytics loader

Source: src/app/layout.tsx:26-28,135-151; src/components/LeadForm.tsx; src/components/QuizApp.tsx; src/components/SamplePaperGate.tsx.

The GA loader is present in production. Repository searches found no explicit quiz, download or successful-lead event instrumentation. Enhanced measurement or externally configured tracking was not inspected, so this does not mean all analytics is absent.

Track quiz_start, quiz_complete, successful lead submission and paper-download clicks with useful placement/landing-page parameters. Record a lead event only after a confirmed accepted outcome; distinguish existing-lead submissions if needed. Do not send names, email addresses or phone numbers to analytics. A click to an external document API measures intent to download, not confirmed PDF delivery.

Use Search Console for query impressions, clicks, CTR, landing pages and indexing. Join these with GA4 organic sessions and qualified lead outcomes. Monitor branded and non-branded searches separately.

### 13. Content rendering needs server-side HTML validation

Source: src/app/blog/[slug]/page.tsx:148-150,212,223,236,265,345; src/components/admin/RichTextEditor.tsx.

CMS HTML and several JSON-LD payloads are rendered without a visible sanitization/escaping boundary. Validate rich text against an allowlist before persistence/rendering, restrict unsafe elements/attributes/URLs and escape '<' in JSON-LD serialization. This also prevents malformed pasted content from undermining headings and layout. Do not treat trusted-editor access alone as sufficient content validation.

## Growth opportunities after the corrections

### Improve existing pages before creating overlapping articles

| Search intent | Current asset | Recommended change |
| --- | --- | --- |
| OPRA syllabus | /syllabus and syllabus blog | Keep /syllabus as the main reference; correct or differentiate the supporting article and cross-link it |
| OPRA eligibility for Indian pharmacists | Existing eligibility article | Improve its qualification-specific answers and source citations; keep the existing URL |
| Registration and exam dates | /exam-dates and registration article | Separate schedule lookup from application procedure; link both ways |
| Sample paper/PDF | /sample-papers and PDF article | Keep /sample-papers as the practice/download destination; give the article a genuinely distinct purpose or consolidate after checking Search Console |
| OPRA fees | Homepage section and scattered article content | Consider a dedicated evergreen /fees page with dated, cited APC costs and clear distinctions between exam, assessment and other costs |
| Subject-specific practice | Biomedical, pharmacology and therapeutics articles already exist | Link these from relevant /syllabus sections; add medicinal chemistry/biopharmaceutics and pharmacokinetics/pharmacodynamics only after confirming distinct useful coverage |
| Calculations and study planning | Existing calculations and working-pharmacist study-plan articles | Add worked examples, reviewed rationales and downloadable planners to those URLs |

The live /syllabus page contains no /blog/... links, despite existing subject guides. Contextual links between the hub, relevant subject pages and appropriate practice resources are a concrete improvement. Avoid adding new near-duplicate pages simply to target another wording/year. Inspect Search Console before merging or redirecting an existing page: overlapping subjects alone do not establish keyword cannibalization.

### Build useful resources that people return to and cite

- Extend the existing question bank into clearly scoped subject practice pages with substantive server-rendered questions, answers and explanations. The current quiz renders only its first question in initial HTML; its 20 interactive questions do not automatically become 20 searchable resources.
- Keep the existing ungated sample questions. Offer the full reviewed pack as an optional next step. Verify the external document link works for the intended user session; the small local PDFs are not the active download target.
- Align promotional copy with the current 20-question quiz. Some blog CTAs still describe a five-question test or a five-minute experience.
- Publish an original study planner, syllabus checklist and annotated calculation examples. Link each resource from the relevant existing guide.
- Distribute genuinely useful extracts through pharmacy colleges, alumni networks, relevant communities and short educational videos. Seek editorial references to useful resources rather than purchased links. This is a proposed acquisition strategy; no backlink or audience-demand analysis was available.
- Add opt-in reminders or study updates if they fit the product, using clear consent and useful session-specific information.

### Make content maintenance sustainable

Keep stable URLs and update year-specific titles/content after verification. The main homepage, syllabus and practice pages still emphasize 2026 while 2027 articles already exist. Do not blindly replace every year: distinguish archived sessions from upcoming preparation. Centralize exam schedules and cutoff timestamps; VerifiedExamDates.tsx currently uses midnight/end-of-day boundaries for some 2027 sessions while exam-dates/page.tsx uses 09:00/17:00. Verify the official time before choosing either value. Show actual review dates and authoritative sources.

### Measure mobile performance before restructuring pages

Run mobile PageSpeed/Lighthouse and inspect Search Console field data when available. Target good 75th-percentile Core Web Vitals: LCP <= 2.5 seconds, INP <= 200 ms and CLS <= 0.1. The large decoded HTML documents justify inspection, but do not establish a failure. Evaluate long-page markup and client payloads, CMS images/embeds, layout stability and repeated data reads. Add reduced-motion handling for decorative infinite animations in globals.css/MedicalBackground.tsx. The shared OG image is a social preview asset; its file size is not evidence that it is the page's LCP problem.

Performance reference: https://web.dev/articles/vitals

### Do not prioritize low-value SEO work

FAQ schema is already abundant. Google limits FAQ rich results to eligible authoritative government/health sites, so do not assume more FAQ markup will expand this site's snippets. Keep useful visible FAQs and truthful markup. Meta-keyword expansion and sitemap priority tweaking are also poor priorities compared with content accuracy, discovery, authority and measured user outcomes. Do not create an artificial SEO score or promise a traffic multiplier without baseline data.

FAQ reference: https://developers.google.com/search/blog/2023/08/howto-faq-changes
